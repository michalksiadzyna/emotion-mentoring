FULLY AUTOMATABLE

Archive.org

Full CLI + Python API + REST S3 API available. Cover can be replaced programmatically with zero browser interaction.
1 Python Library (internetarchive) Installed
internetarchive v5.8.0 is already installed on this machine. The library provides upload() and modify_metadata() functions that work directly against the IAS3 API.
Replace a file on an existing item:
import internetarchive as ia item = ia.get_item('your-item-identifier') item.upload( {'cover.jpg': '/path/to/new-cover.jpg'}, queue_derive=False )
Uploading a file with the same name as an existing file overwrites it automatically. The old version is preserved in history/files/ by default (can be disabled with header x-archive-keep-old-version:0).
2 IAS3 REST API (Direct HTTP)
Archive.org exposes an S3-compatible REST API. A single PUT request replaces any file:
curl --location \ --header "authorization: LOW $accesskey:$secret" \ --header "x-archive-queue-derive:0" \ --upload-file new-cover.jpg \ https://s3.us.archive.org/ITEM-ID/cover.jpg
API keys obtained at archive.org/account/s3.php.
3 Metadata Update (Item Image designation)
After uploading the cover file, it can be designated as the item thumbnail via metadata modification:
ia.modify_metadata( 'your-item-identifier', metadata={'cover_image': 'cover.jpg'} )
Alternatively, naming the file *_itemimage.jpg signals the system to use it as the item thumbnail. Processing takes a few minutes after upload.
4 Authentication Setup
Three configuration methods:
  • Config file: Run ia configure (or python -m internetarchive configure) — stores credentials in ~/.config/ia.ini
  • Environment variables: IA_ACCESS_KEY_ID and IA_SECRET_ACCESS_KEY
  • Inline dict: Pass access_key and secret_key directly to upload/modify functions
MANUAL BROWSER ONLY

Draft2Digital

No public API exists. All cover updates require logging into draft2digital.com through a browser. However, a single update here cascades to 6+ downstream platforms.
1 No Public API Manual
Draft2Digital has no publicly documented API, no developer portal, no REST endpoints, and no CLI tool. The entire workflow — uploading covers, updating metadata, managing distribution — happens exclusively through their web dashboard at draft2digital.com.
2 Cascade Effect (High Value) 6+ platforms
One cover update on D2D automatically propagates to all connected retail channels:
  • Apple Books
  • Barnes & Noble (Nook)
  • Kobo
  • Smashwords
  • Library networks (OverDrive, BorrowBox, etc.)
  • Everand (formerly Scribd)
Ebook changes push immediately at no charge. Print cover changes: one free submission per 90 days.
3 Browser Automation Feasibility
Playwright or Selenium could automate the D2D dashboard flow: login → navigate to book → upload new cover → submit. This is a viable path if cover updates become frequent. The D2D interface is a standard web app with no known anti-bot measures beyond standard authentication.
SEMI-AUTOMATABLE

Google Play Books Partner Center

No direct upload API for individual publishers. Two paths exist: manual web upload, or SFTP/FTP automated content fetching (requires Google setup).
1 No Publisher Upload API Manual
The Google Books API (googleapis.com/books/v1) is read-only — it retrieves book metadata and search results. It has no endpoints for uploading content or covers. The Partner Center web interface at play.google.com/books/publish is the primary upload method for individual publishers.
Cover upload path: Book Catalogue → Select book → Content tab → Upload a file. Accepted formats: JPEG, PNG, TIFF, PDF. Minimum 640px, max 7200px per dimension.
2 Automated Content Fetching (SFTP/FTP/GCS)
Google offers an automated content fetching system for publishers who host files on their own servers. Google periodically crawls the server on a schedule and ingests updated files.
  • Protocols: HTTP, HTTPS, SFTP, FTP, Google Cloud Storage
  • Cover format: JPEG, named as eISBN.jpg
  • Metadata: ONIX 2.0, 2.1, or 3.0 feed
  • Setup: Requires contacting Google to configure the crawler for your server
This is designed for publishers with large catalogs. Google must configure the crawler on their end after you fill out a setup form. The schedule is predefined by Google, not on-demand.
For a single book, the setup overhead outweighs the benefit. This is viable only if you scale to a significant catalog.
3 Browser Automation Feasibility
Playwright automation of the Partner Center is technically possible but carries risk. Google services use advanced bot detection (reCAPTCHA, device fingerprinting). Automated login to a Google account from a script may trigger security challenges or account flags. This is the riskiest platform to automate via browser.
AUTO-CASCADE FROM D2D

Books2Read

No API. Cover images on Universal Book Links (UBLs) do not auto-sync after initial creation — requires manual refresh through the D2D/Books2Read dashboard.
1 No API, Manual Dashboard Manual
Books2Read (owned by Draft2Digital) has no public API. The author dashboard allows editing Book Tabs and Author Pages through a web interface. Cover images are pulled once when the Universal Book Link is first created and are not automatically updated when the source cover changes.
To update a Books2Read cover: log into the D2D dashboard → navigate to the Book Tab → enter Edit Mode → update the cover image manually.
2 D2D Distribution Cascade
If the book is distributed through D2D, the cover on retail storefronts (Apple Books, B&N, Kobo, etc.) updates automatically via the D2D cascade. The Books2Read aggregator page is a separate entity that needs its own manual update. This is a one-time fix per cover change.
